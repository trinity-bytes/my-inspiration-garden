# Media thumbnails and texture load smoothing
Objective: Stop canvas scroll jank (worst on mobile) caused by cards downloading and decoding full-size originals; cards load small WebP thumbnails and video posters, originals load only in the detail view.
Branch: perf/media-thumbnails (from develop); delivery: one branch, one Conventional Commit per work unit, ready to push (push/PR/release owner-approved); forecast: ~900 authored lines; runner: mise exec -- pnpm test.

## Specs
S1. Card thumbnails are WebP, generated by the Worker with the Cloudflare Images binding ("Worker + CF Images"), stored once in R2 and served immutable; one transformation per variant.
S2. Canvas cards load the thumbnail variant for R2-stored images, link previews and video posters; the original only loads in the detail view.
S3. If a thumbnail cannot be generated (binding unavailable, quota, non-image), the card still shows the original (graceful fallback, never a broken card).
S4. Uploaded videos: "optimizar la carga de videos para que solo se cargue cuando sea necesario" — the canvas never downloads the video file; a poster image is captured in the browser at upload and stored as `data.thumbnail`; the detail player loads the video only on play (poster shown until then).
S5. Existing media is covered: image thumbnails are generated lazily on first request (self-backfill); existing uploaded videos get posters via a one-off script (ffmpeg + write token, `--dry-run` first).
S6. Complement (B): decode/downscale card images off the main thread (`createImageBitmap` with resize) instead of drawing full bitmaps on the main thread.
S7. Complement (B): texture paints/uploads landing in the same frame are spread with a per-frame budget, and the texture cache no longer evicts textures a normal scroll revisits.
User wording: "prefiero que arranques por A porque es algo que realmente ataca el problema, luego le ponemos B como complemento. prefiero una solucion de ingenieria a primero probar parches"
